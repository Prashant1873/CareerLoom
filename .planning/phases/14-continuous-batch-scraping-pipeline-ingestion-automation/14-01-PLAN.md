<objective>
Implement the high-throughput async batch scraping core engine (`BatchScrapeRunner`), hardened stale job reconciler with data-loss guard, permanent stale job purger, and the standalone `sync_batch.py` CLI runner with rich metric reporting.

Requirements covered: BATCH-01, BATCH-02.
Security Threats mitigated: T-14-02 (Data Destruction), T-14-03 (ATS Host Flooding), T-14-04 (Stale Data Accumulation).
Output: `backend/app/services/batch_runner.py`, upgraded `backend/app/db/database.py`, CLI script `backend/scripts/sync_batch.py`, and test suite `tests/test_batch_runner.py`.
</objective>

<threat_model>
ASVS Level: 1
Threats:
- T-14-02 (HIGH): Silent Data Destruction — Intermittent network timeouts or ATS 429 errors cause `fetch_jobs` to return 0 jobs, falsely marking all active company jobs as closed/inactive.
  Mitigation: `reconcile_target_jobs` requires `is_successful_fetch=True`. If `is_successful_fetch=False` (exception/timeout/error), leave existing listings untouched and record `career_targets.last_status = 'error'`.
- T-14-03 (MEDIUM): Upstream ATS Host Flooding — Concurrent requests to the same ATS endpoint (e.g. 50 Greenhouse targets simultaneously) lead to IP ban / 429 rate limiting.
  Mitigation: Bounded global concurrency via `asyncio.Semaphore(15)` and per-host delay jitter (100-300ms).
- T-14-04 (LOW): Stale Data Accumulation — Indefinite accumulation of soft-archived jobs degrades SQLite B-Tree performance over time.
  Mitigation: Implement `purge_stale_jobs(days_inactive=30, dry_run=False)` to permanently prune dead postings.
</threat_model>

       - If `dry_run` is True: queries `SELECT COUNT(*) FROM jobs WHERE is_active = 0 AND (last_seen_at < ? OR last_seen_at IS NULL)` and returns count without mutating.
       - If `dry_run` is False: executes `DELETE FROM jobs WHERE is_active = 0 AND (last_seen_at < ? OR last_seen_at IS NULL)`, commits transaction, and returns `cursor.rowcount`.

       - Initializes `JobSyncService` instance.
       - Manages bounded concurrency via `asyncio.Semaphore(self.concurrency)`.
       - Manages per-host jitter: tracks `_last_host_time: Dict[str, float]` for ATS domain hosts (`boards-api.greenhouse.io`, `api.lever.co`, `api.ashbyhq.com`, etc.) and sleeps 0.1 to 0.3s when same host was queried immediately prior (T-14-03).
       - Method `async def scrape_target(self, target: CareerTarget, dry_run: bool = False) -> Dict[str, Any]`:
         - Isolated try/except block.
         - Fetches jobs using appropriate ATS connector (`greenhouse`, `lever`, `ashby`, `smartrecruiters`, `workday`) or `portal_extractor`.
         - On success: applies India country tagging if Indian startup/unicorn, calls `upsert_jobs(jobs)` (unless dry_run), and calls `reconcile_target_jobs(..., is_successful_fetch=True)` (unless dry_run).
         - On exception: logs error with traceback suppression, calls `reconcile_target_jobs(..., is_successful_fetch=False)` to record error status without deactivating jobs (T-14-02).
       - Method `async def run(self, targets: Optional[List[CareerTarget]] = None, tier: Optional[str] = None, domain: Optional[str] = None, limit: Optional[int] = None, dry_run: bool = False, purge_stale_days: Optional[int] = None, progress_callback: Optional[Callable[[Dict[str, Any]], None]] = None) -> BatchScrapeResult`:
         - Loads targets from DB if not provided (`get_targets(params)`).
         - Executes `scrape_target` concurrently via `asyncio.gather(*tasks)`.
         - Calls `progress_callback` on each completed target if provided.
         - Runs `purge_stale_jobs(days_inactive=purge_stale_days, dry_run=dry_run)` if `purge_stale_days` is provided.
         - Calculates elapsed time and throughput, returning `BatchScrapeResult`.
